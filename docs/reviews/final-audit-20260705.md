## A. ユーザー影響あり

### A-1 [high] 並行書き出しで一時ファイル掃除が相手の書き出しを全損させる
- **箇所**: `VideoExporter.swift:1836-1860`（呼出 592, 1436）
- **影響**: ウィンドウAで15時間動画を書き出し中、ウィンドウB（⌘N「新規ウィンドウ」は正式導線）が同じフォルダへ書き出し開始すると、Bの開始時掃除がAの生きた `.avs_tmp_*` チャンクを全削除。Aは数時間後の結合フェーズで全損。GUIとヘッドレスQAの同時実行でも同じ。A-5経由なら単一ウィンドウでも成立。
- **根拠**: 掃除はプレフィックス一致のみで年齢・所有者・使用中判定なし（2エージェントが独立に発見、コード実読で確認）。
- **是正**: エクスポート毎に一意サブディレクトリ `.avs_tmp_<UUID>/` を掘り自分のものだけ defer 削除。起動時掃除は更新時刻が十分古い（例: 24時間超）ものに限定。

### A-2 [high] テーマ/プロジェクトの色が保存・読込のたびに変色していく
- **箇所**: `OverlayRenderer.swift:1403-1426`（.avstheme）、`TextOverlay.swift:267-287`（.avsproj のテキスト色）
- **影響**: 保存→読込を繰り返すたびに色が明るく漂う。**実測**: (0.3, 0.8, 0.3) → 2周で (0.349, 0.821, 0.371) → 3周で (0.404, 0.840, 0.446)。deviceRGB 成分で保存するためディスプレイプロファイル依存でもあり、他の Mac に渡した .avstheme は別のずれ方をする。
- **根拠**: エンコードは `usingColorSpace(.deviceRGB)` の成分、デコードは `CGColor(red:...)`（GenericRGB）で色空間が非対称。監査エージェントと監査主体が独立にスニペット再現。
- **是正**: エンコード/デコードとも固定 sRGB に統一（`CGColor(colorSpace: sRGB, components:)` で復元）。既存ファイルは sRGB 解釈で読み込めば自然収束。

### A-3 [med] 音声トラックが映像よりわずかに短い素材で書き出し全体が失敗する（#88×#90 相互作用）
- **箇所**: `VideoExporter.swift:717`（インライン挿入）、`1750-1760` 付近（mux 挿入）
- **影響**: 音声挿入範囲は映像基準のフレーム演算から作られ、音声トラック自身の範囲と交差（クランプ)していない。音声が映像より短い MP4（コンテナとして普通に起きる）で範囲超過 → #90 で fatal 化されたため「音声のコピーに失敗しました」で書き出し全体が失敗。#90 以前は try? で黙殺されていたため顕在化しなかった。
- **是正**: 挿入前に `CMTimeRangeGetIntersection(range, audioTrack.timeRange)` でクランプし、空のときのみスキップ。実際の読込失敗は従来どおり throw。

### A-4 [med] 空き容量チェックは×2だが実ピークは約×3
- **箇所**: `VideoExporter.swift:1320-1323 / 1513-1516`（チャンク defer 削除）vs `1394-1410 / 1590-1606`（結合→mux）
- **影響**: チャンク削除は defer のため mux **後**。mux 中はチャンク群(≈1×)＋映像のみ中間(≈1×)＋書き込み中の最終出力(→1×)が同時存在。長時間・高ビットレートで「数時間エンコード後、最終段でディスクフル」。
- **是正**: `concatenateExportedFiles` 成功直後にチャンク temp を即削除してピークを×2に抑える（最小修正）。

### A-5 [med] 書き出し中に Esc/⌘Q の保護がない
- **箇所**: `PreviewView.swift:60-67`（進捗シート）、`PreviewViewModel.swift:692-693`（終了確認）、`ExportViewModel.swift:276-278`（quitWhenDone）
- **影響**: ①進捗シートは Esc で閉じられ VM ごと破棄 — 書き出しは裏で継続するが進捗・キャンセル手段を喪失、スリープ抑止トークンも解放（途中スリープあり得る）、再エクスポート可能になり A-1 が単独ウィンドウで発火。②終了確認は未保存編集しか見ておらず、書き出し中でも ⌘Q が素通り。③quitWhenDone は他ウィンドウの進行中書き出しを道連れに terminate。
- **是正**: `.interactiveDismissDisabled(isExporting)`、終了ゲートに「書き出し中」判定を合流、quitWhenDone は他ウィンドウの isExporting 確認後に terminate。

### A-6 [med] マルチウィンドウで未保存保護・ファイルオープンが最後の1枚にしか効かない
- **箇所**: `ActivityVideoStudioApp.swift:17-59`（AppTerminationCoordinator / AppFileOpenCoordinator）
- **影響**: 単一 owner 制のため、ウィンドウB を開くと owner が B に上書き。B を閉じると owner=nil → `canTerminate()` は常に true になり、ウィンドウA の未保存編集が ⌘Q で無警告破棄。openFile も最後の登録ウィンドウのみに配送。
- **是正**: ownerID→クロージャの辞書で全ウィンドウ分を保持。terminate は全員の AND、open はキーウィンドウへ。

### A-7 [med] ヘッドレス書き出しで ELEV GAIN が全編「+0 m」（QA の信頼性・GUI と不一致）
- **箇所**: `ActivityVideoStudioApp.swift:547`
- **影響**: ヘッドレスは `renderer.allDataPoints = pts` 後に `buildElevationGainCache()` を呼ばず、累積獲得標高が常に 0 表示。**本監査までの QA 出力全てで実際に発現していた**（活動終端 11.3/11.3 KM のフレームでも +0 m）。GUI 書き出しは正常。
- **是正**: 1行追加（`renderer.buildElevationGainCache()`）。恒久策は `allDataPoints.didSet` で再構築（B-6 と同根）。

### A-8 [med] FIT 同期できない区間ではテキストオーバーレイが書き出しから黙って消える
- **箇所**: `VideoExporter.swift:747-752` vs `OverlayView.swift:23-42`
- **影響**: コンポジタはデータポイントが取れないと素通し（テキスト含む全オーバーレイをスキップ）する一方、プレビューはテキストを表示する。FIT 未読込プロジェクト（動画＋テロップのみの利用）や撮影日時なし動画の混在セグメントで、プレビューで見えているテロップが出力に焼き込まれない。
- **是正**: データポイントが nil でもテキストオーバーレイだけは描画する経路を追加。

### A-9 [med] CORE TEMP の形状フォールバックが denormal float で誤検知する
- **箇所**: `FITParser.swift:1215, 1264-1266`
- **影響**: field_description の無い他社アプリの4バイト整数フィールド（devDataIndex==0, fieldNumber 0/10）を `Float(bitPattern:)` 再解釈すると、生値空間の約26%が (0,50) の float に落ちる（例: 生値250 → 3.5e-43 → 判定通過 →「CORE 0.0°C」誤表示）。
- **是正**: denormal 排除（`value.isNormal`）＋妥当域を体温らしい範囲（25〜45°C）へ。

### A-10 [med] GRADE フォールバックが毎フレーム最大 O(n) の線形走査
- **箇所**: `FITDataPoint.swift:46`（呼出 `OverlayRenderer.swift:253`, `OverlayView.swift:183`）
- **影響**: FIT に grade フィールドが無い通常記録で、カメラがアクティビティ開始前から回っている区間は現在距離≈0 のため `lastIndex(where:)` が**末尾から全点走査して結局 "--%"**。5.4万点×プレビュー30fpsで実害（書き出しは0.25s量子で緩和）。distance は単調なので線形の必然性がない。
- **是正**: 二分探索に置換（`cumulativeElevationGain` と同じ形）。

### A-11 [med] 審査提出スクリプトが処理中の新ビルドを追い越して旧ビルドを提出しうる
- **箇所**: `scripts/appstore/submit.sh:11-12`（`asc.py:116-121`）
- **影響**: アップロード直後（新ビルドが PROCESSING）に submit.sh を実行すると、`--state VALID` フィルタが新ビルドを除外し、1つ前の VALID ビルドを無警告で審査提出。発覚は数日後。
- **是正**: 状態フィルタ無しの最新と VALID 最新を比較し、不一致なら「より新しいビルドが処理中」と警告して exit。

## C. 問題なしを確認した領域（要点）

- **#88 フレーム演算**: Int64 オーバーフローなし（15h・240fps でも余裕）、ceil/floor＋許容誤差は十分、チャンクは隙間・重複なくタイル、VFR でも時間軸連続で実害なし
- **キャンセル・エラーパス**: 全フェーズで検知、reader/writer/session の後始末、progressPollingTask の回収に漏れなし
- **進捗位相**（#98×#88）: 0→0.99→0.995→1.0 で単調、ViewModel の単調ガードが順序逆転を吸収
- **HDR/色設定**（#89）: HEVC Main10 分岐・SDR フォールバックとも compression プロパティ欠落なし
- **メモリ・大容量**: 全経路ストリーミング、オーバーレイキャッシュは単一エントリ、配列は高々数十要素
- **スレッド安全性**: `render()` の呼出はコードベースで1箇所のみ・キャッシュの NSLock 内で直列化、レンダラとキャッシュは常に1:1、プレビューは render() 非使用（ライブレイヤ）
- **スナップショット独立性**（#108）: ExportSnapshot は末端まで値型、書き出し中の UI 操作が出力へ混入する経路なし
- **FIT堅牢性**: CRC（header/file・0x0000スキップ）、エンディアン一貫、スライス正規化、圧縮タイムスタンプ展開の数学、developer field の複合キー、座標二重防御
- **シークレット**: 現ツリーに Key ID・.p8・トークン類の残置ゼロ（Team ID は署名に必要な非秘密として意図的に残置）
- **entitlements/署名/バージョン管理**: sandbox・hardened runtime・app-scope ブックマーク・plist/pbxproj の整合を確認

## 棄却した指摘（誤検知）

- **「OverlayRenderer.makeExportCopy が MainActor 保護なしで書き出し中の UI 編集と競合」** — `makeExportViewModel()`（`PreviewViewModel.swift:1801-1812`、@MainActor）がシート生成時にコピーを確定し、以後の書き出しはその私有コピーのみを参照するため成立しない。ただし、この安全性は「シート生成時にコピーする」呼出規約に暗黙依存しているため、コメントまたはアサーションで明文化する価値はある。
